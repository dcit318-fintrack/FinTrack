# FinTrack Data Model Specification


## 1. Overview & ERD Relationships

The FinTrack database is built on a relational architecture centered around ASP.NET Core Identity's ApplicationUser. All financial metrics (Transactions, Budgets, Savings Goals) are strictly isolated per user.

[ApplicationUser (string Id)]
    ├── (1:N) ──> [Transaction] <── (N:1) ── [Category]
    ├── (1:N) ──> [Budget]      <── (N:1) ── [Category]
    └── (1:N) ──> [SavingsGoal]



## 2. Table Schemas & Column Specifications

### A. ApplicationUser (Extends IdentityUser)
Managed via ASP.NET Core Identity. Custom properties added to the base user model.

| Column Name | Data Type       | Nullable | Description / Constraints                           |
|             |                 |          |                                                     |
| Id (PK)     | `string`        | No       | Primary Key generated by ASP.NET Core Identity.     |
| FullName    | `nvarchar(100)` | No       | User's full name.                                   |
| CreatedAt   |  `datetime2`    | No       | Timestamp when the  user account was created (UTC). |
| Email       | `nvarchar(256)` | No       | Inherited from `IdentityUser`.                      |
| PasswordHash| `nvarchar(max)` | No       | Inherited from `IdentityUser`.                      |



### B. Category
Lookup table for grouping transactions and budgets. System defaults are seeded.

| Column Name | Data Type      | Nullable | Description / Constraints              |
|             |                |          |                                        |
| Id (PK)     | `Guid`         | No       | Primary Key.                           |
| Name        | `nvarchar(50)` | No       | Category name (e.g., Food, Transport). |
| Type        | `nvarchar(10)` | No       | Must be `"Income"` or `"Expense"`.     |



### C. Transaction
Stores all income and expense ledger entries.

| Column Name   | Data Type       | Nullable  | Description / Constraints                         |
|               |                 |           |                                                   | 
| Id(PK)        | `Guid`          | No        | Primary Key.                                      |
| UserId(FK)    |  `string`       | No        | Foreign key pointing to `ApplicationUser.Id`.     |
| CategoryId(FK)| `Guid`          | No        | Foreign key pointing to `Category.Id`.            |
| Amount        | `decimal(18,2)` | No        | Transaction amount (must be > 0).                 |
| Type          | `nvarchar(10)`  | No        | Must be `"Income"` or `"Expense"`.                |
| Description   | `nvarchar(200)` | No        | Max length 200 characters.                        |
| Date          | `datetime2`     | No        | Transaction date in UTC. Cannot be in the future. |



### D. Budget
Defines a monthly spending limit per category for a specific user.

| Column Name   | Data Type       | Nullable | Description / Constraints                     |
|               |                 |          |                                               |
| Id (PK)       | `Guid`          | No       | Primary Key.                                  |
| UserId(FK)    | `string`        | No       | Foreign key pointing to `ApplicationUser.Id`. |
| CategoryId(FK)| `Guid`          | No       | Foreign key pointing to `Category.Id`.        |
| Limit         | `decimal(18,2)` | No       | Monthly spending cap.                         |
| Month         | `nvarchar(7)`   | No       | Format: `"YYYY-MM"` (e.g., `"2026-08"`).      |

*Note: `Spent` and `Remaining` amounts reported in `/api/budgets` are calculated dynamically at query-time using SQL aggregations over the `Transaction` table.*

---

### E. SavingsGoal
Tracks long-term saving targets for users.

| Column Name   | Data Type       | Nullable  | Description / Constraints                     |
|               |                 |           |                                               |
| Id (PK)       | `Guid`          | No        | Primary Key.                                  |
| UserId (FK)   | `string`        | No        | Foreign key pointing to `ApplicationUser.Id`. |
| Name          | `nvarchar(100)` | No        | Name/description of the goal (e.g., "Laptop").|
| TargetAmount  | `decimal(18,2)` | No        | Total goal target.                            |
| CurrentAmount | `decimal(18,2)` | No        | Current accumulated funds (default `0.00`).   |
| TargetDate    | `datetime2`     | No        | Planned achievement date (UTC).               |



## 3. Data Integrity, Foreign Keys & Unique Rules

1. **Precision Standard:** All monetary fields (`Amount`, `Limit`, `TargetAmount`, `CurrentAmount`) are strictly defined as `decimal(18,2)` to prevent floating-point precision loss.
2. **Cascade Delete Behavior:**
   * **User Deletion:** Deleting an `ApplicationUser` results in a `CASCADE` delete for all linked `Transactions`, `Budgets`, and `SavingsGoals`.
   * **Category Deletion:** Deleting a `Category` is set to `RESTRICT` (Block) to prevent orphaned financial records.
3. **Unique Constraints:**
   * **Budget Uniqueness:** Compound unique constraint on `(UserId, CategoryId, Month)`. A user cannot have duplicate budgets for the same category within the same month.
4. **Performance Indexes:**
   * **Composite Index on `Transaction(UserId, Date)`:** Optimizes filtered date queries and report aggregation endpoints (`/api/reports/spending-by-category`, `/api/reports/income-vs-expense`, `/api/dashboard`).

## 4. Seed Data (Categories)

The following default categories will be seeded into the database:

| Category Name | Type    | Description                                 |
|               |         |                                             |
| Food          | Expense | Groceries, dining out, and food delivery.   |
| Transport     | Expense | Public transit, fuel, vehicle maintenance.  |
| Rent          | Expense | Monthly housing costs.                      |
| Utilities     | Expense | Electricity, water, internet, subscriptions.|
| Entertainment | Expense | Leisure, movies, events.                    | 
| Salary        | Income  | Monthly payroll and primary income.         |
| Other         | Expense | Miscellaneous expenses.                     |



## 5. Local Database Setup & Migrations Guide

### Prerequisites
* Local PostgreSQL / SQL Server instance running.
* `.NET 8 SDK` and `dotnet-ef` tool installed.

### Configuration
1. Open `FinTrack.Server/appsettings.Development.json`.
2. Configure your local connection string:
   ```json
   {
     "ConnectionStrings": {
       "DefaultConnection": "Server=localhost;Database=FinTrackDb;User Id=sa;Password=YourPassword123!;TrustServerCertificate=True;"
     }
   }
